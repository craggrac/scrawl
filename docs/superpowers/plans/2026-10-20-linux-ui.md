# Linux phase 4: the GPUI app (pill, review, tray, `scrawl app`)

Goal: the same app the macOS build runs: a long-lived process with the recording pill, the
review window and a status menu, driven by the capture shortcut. Shared GPUI code (the pill,
chips, picker and review views, the coordinator) is compiled on Linux unchanged; only the
platform calls differ. Ink/laser overlay and the picker's dim/cutout are phase 5; settings
window is phase 4 part 2.

## Findings (spike, 2026-10-20)

- gpui **0.2.2** (the version macOS uses) builds on Linux with `features = ["font-kit",
  "wayland"]` and runs on Hyprland 0.56: transparent windows (`WindowBackgroundAppearance::
  Transparent`), text, `canvas` + `PathBuilder` strokes all work. No gpui fork or git pin.
- gpui 0.2.2 depends on `xattr 0.2.3`, which uses `libc::ENOATTR`, removed from libc on Linux
  in 0.2.190+. Fix: vendor `xattr-0.2.3` under `vendor/` with a one-line cfg (`ENODATA` on
  Linux/Android) and `[patch.crates-io] xattr = { path = "vendor/xattr-0.2.3" }`. macOS
  compiles the original line unchanged.
- gpui 0.2.2 cannot position, pin or unfocus windows on Wayland. Hyprland does it: a runtime
  rule via `hyprctl eval 'hl.window_rule({ match = { class = "^(scrawl-pill)$" }, float = true,
  pin = true, no_focus = true, border_size = 0, no_shadow = true, no_blur = true, move = {...},
  size = {...} })'` (Lua config, Hyprland ≥ 0.53; older: `hyprctl keyword windowrulev2`). Rules
  are session-only, so the app installs them at startup; the user's config is never edited.
  Windows are told apart by `app_id` (`WindowOptions::app_id`): `scrawl-pill`, `scrawl-review`,
  `scrawl-picker`.

## Architecture

- **`platform` seam.** `src/platform/mod.rs` re-exports, under the names `ui.rs` already uses,
  either the macOS items (`capture::mac::*`, `laser_overlay`, `native::pill`, `sparkle`,
  window chrome helpers) or `src/platform/linux.rs`. macOS-side edits are moves and `use`
  path changes only. Items the coordinator only needs as types on Linux (iPhone session,
  native pill, Metal overlay) get small Linux stand-ins whose constructors return "not
  available", so the code paths that use them are never taken.
- **Portable state out of mac files.** `LiveOverlayEvent` moves to `capture/mod.rs`;
  `SelectionMode` to a portable module so `hold.rs` compiles; `icons`, `inbox`, `hold`,
  `screens` geometry and `sketch::timeline` ungated.
- **Linux capture session.** `platform::linux::ScreenCaptureSession` wraps the phase 2/3
  pieces (`linux::record::ScreenSession`, `AudioRecorder`, `InputRecorder`,
  `hypr::WindowLogger`) behind the macOS session's `start / elapsed_ms / stop` shape, and
  `finish_session` returns the input events.
- **Targets and screens.** From Hyprland IPC: monitors (`screens::current`), cursor
  (`current_mouse_screen`), windows (`list_selectable_windows`, `selectable_window_at`),
  regions (`region_target`), reusing `linux::hypr`.
- **Window chrome.** `float_window`/pill placement become Hyprland rules (above) installed
  once; `remember_front_app`/`hand_back_keys` refocus the previous window via
  `hyprctl dispatch focuswindow address:…`; `reduce_motion` false; `stay_out_of_dock` no-op.
  The pill draws its own shell (`has_shell == false` path that already exists).
- **Tray.** `ksni` (StatusNotifierItem over D-Bus, Unlicense, pure Rust) with the same
  `MenuAction`s as the macOS status menu (Record, Choose target, Open latest, Inbox, Settings,
  Quit). Needs a tray host (waybar `tray`, Noctalia's bar) — documented.
- **Lifecycle.** `scrawl app` (start with Hyprland `exec-once`) owns
  `$XDG_RUNTIME_DIR/scrawl/ctl.sock` (0700 dir, single instance). `scrawl toggle` writes
  `toggle` to it; if no app is listening it falls back to the headless pidfile flow from
  phase 2. Commands feed the coordinator's existing flume channel as
  `LiveOverlayEvent::CaptureShortcut`.
- **Hold-to-switch.** The macOS hold logic needs key-up of the shortcut; on Linux the evdev
  reader (phase 3) already sees it, so `InputRecorder` grows a mode that reports the shortcut's
  press/release to the telemetry while the app runs.
- **Clipboard/paste.** Copy as today (`wl-copy`); "paste into the previous app" stays macOS-only
  for now (Wayland has no synthetic paste without a virtual keyboard; phase 6).

## Safety net for macOS

This machine cannot link macOS, but `cargo check --target aarch64-apple-darwin` type-checks the
Rust side if the build scripts allow it (to be confirmed). If it works, every task runs it;
if not, macOS edits stay mechanical and are listed in each commit.
